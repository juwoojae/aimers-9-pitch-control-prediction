# 결정 및 이슈 기록

## 상태 표기

- `확정`: 공식 규정 또는 데이터로 검증됨
- `결정`: 팀이 근거를 갖고 선택함
- `가설`: 실험 전 아이디어
- `미확정`: 추가 확인 필요

## 기록

### 2026-08-10 — 재현 코드와 문서 구조 단순화

- `결정` 최종 학습에 필요한 전처리·검증·HGB 구성을 루트의 `train.py` 하나로 통합한다.
- `결정` 제출 실행은 `script.py`, 제출 패키징은 `build_submission.py`로 역할을 분리한다.
- `결정` 탐색용 스크립트와 중간 보고서는 최종 수치와 선택 근거를 README로 옮긴 뒤 제거한다.
- `근거` 최종 모델의 학습 과정과 제출 경로를 세 실행 파일만 읽어도 재현할 수 있게 하고, 실험 중간 산출물과 최종 코드를 혼동하지 않게 한다.
- `확정` 통합된 `train.py`의 두 모델명, 가중치, 피처 목록(47개·43개)은 기존 `model/rf.pkl`과 일치한다.
- `확정` 구조 변경 후 기존 9개 단위 테스트와 5행 샘플 추론이 통과했다.

### 2026-08-09 — 제출 오류 대응 및 Linux 서버 재검증

- `확정` 운영진 `baseline_submit.zip`은 명시적 `model/` 엔트리, Unix ZIP 메타데이터, 파일 권한 `0644`를 포함한다.
- `확정` 기존 Windows `Compress-Archive` 결과는 파일 경로는 맞지만 명시적 디렉터리 엔트리와 Unix 메타데이터가 없었다.
- `결정` 전용 빌드 코드로 운영진 베이스라인과 같은 ZIP 엔트리·권한을 생성한다.
- `확정` 공식 평가 페이지는 입력 경로를 표에서는 `data/`, 하단에서는 `open/`으로 서로 다르게 안내한다.
- `결정` 공식 배포 베이스라인의 `data/`를 우선 사용하되 `open/`도 안전하게 탐색한다.
- `확정` Linux, Python 3.11.15, 공식 라이브러리 버전, 네트워크 차단, 6 CPU·28GB 환경에서 requirements 검사, 모델 로드, 추론, 제출 파일 검증을 통과했다.

### 2026-08-08 — 최종 HGB 앙상블 및 무보정 확률 채택

- `확정` 정확한 경기 ID·경기 내 투구 순서가 없어 `row_id`를 시간 순서로 가정할 수 없다.
- `결정` 2019~2021→2022, 2019~2022→2023, 2019~2023→2024의 시즌 순방향 holdout을 사용한다.
- `확정` 선택 앙상블 BSS는 2022 `2,234.04`, 2023 `0.00`, 2024 `598.33`이다.
- `결정` 전체 허용 피처 HGB와 선수·팀 ID를 제외한 저복잡도 HGB의 확률을 50:50으로 평균한다.
- `결정` sigmoid와 intercept calibration은 다음 시즌 BSS를 안정적으로 개선하지 못했으므로 적용하지 않는다.
- `확정` Trackman 투수·타자 ID와 메인 데이터 ID 값의 교집합은 각각 0이고 공식 대응 키도 없다.
- `결정` 검증되지 않은 추정 조인을 만들지 않고 Trackman을 최종 모델에서 제외한다.
- `확정` 245,789행 전체 `script.py` 실행은 로컬에서 10.79초, 최대 프로세스 트리 RSS는 0.65GiB였다.
- `결정` 추가 패키지 없이 서버 기본 라이브러리만 사용하고 requirements는 주석만 유지한다.

### 2026-08-08 — 모델 아티팩트 서버 버전 호환성

- `확정` NumPy 2.x에서 저장한 첫 아티팩트는 NumPy 1.26.4에서 random bit generator 역직렬화 오류가 발생했다.
- `결정` 해당 아티팩트를 폐기하고 서버와 같은 NumPy 1.26.4·SciPy 1.15.3·scikit-learn 1.8.0 환경에서 최종 모델을 다시 학습·저장했다.
- `확정` 새 아티팩트는 NumPy 1.26.4 환경에서 로드, 5행 전체 추론, 245,789행 전체 추론을 통과했다.

### 2026-08-08 — 제출 추론 안전성 강화

- `결정` test와 sample submission의 행 수·ID 집합·ID 중복을 추론 전에 검사한다.
- `결정` 누락된 예측에 placeholder를 유지하지 않고 즉시 오류를 발생시킨다.
- `결정` 모든 예측값의 개수, 유한성, `[0, 1]` 범위를 저장 전에 검사한다.
- `결정` 추가 패키지를 설치하지 않고 평가 서버 기본 pandas, scikit-learn, joblib을 사용한다.

### 2026-08-08 — 프로젝트 문서 초기화

- `확정` 예측 단위는 개별 투구이며 Target은 `control_success`이다.
- `확정` 출력은 제구 성공 가능성을 나타내는 확률이다.
- `확정` 현재 투구 직전까지 알 수 있는 정보만 사용할 수 있다.
- `확정` 평가 지표는 Brier Skill Score이다.
- `확정` 실제 평가 샘플은 245,789개이고 전체 추론 제한은 10분이다.
- `확정` 제출은 `model/`, `script.py`, `requirements.txt`를 포함한 ZIP 형식이다.
- `확정` Public Score는 테스트 데이터 100%로 계산되고, Private Score는 대회 종료 시점의 Public Score이다.
- `확정` Phase2 수료 기준 Public Score는 `549.51`이다.
- `확정` 평가 서버는 Ubuntu 22.04.5 LTS, Python 3.11.15, CUDA 12.8 환경이다.
- `확정` 최종 실행에 필요한 평가 서버 환경과 라이브러리를 `README.md`에 기록했다.
- `확정` 설치 오류는 일일 제출 횟수에 반영되지 않지만, `script.py` 실행 이후의 제출 오류는 반영된다.
- `확정` 공식 배포 데이터와 베이스라인 제출 예시를 프로젝트에 추가했다.
- `확정` train은 1,475,092행×49컬럼, Trackman은 1,793,078행×30컬럼이다.
- `확정` 로컬 test와 sample submission은 형식 확인용 5행이며 실제 평가 시 245,789행으로 교체된다.
- `확정` 배포 구조와 베이스라인 코드 모두 평가 입력 경로로 `data/`를 사용한다.
- `결정` 데이터 스키마 확인 전에는 구체적인 피처나 split을 확정하지 않는다.
- `결정` 모든 과거 이력 피처는 현재 행을 제외하고 계산한다.
