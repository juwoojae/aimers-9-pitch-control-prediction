# 모델링 프로토콜

이 문서는 데이터 확인 전의 작업 원칙입니다. 실제 컬럼과 시간 구조를 확인하면 구체화합니다.

## 1. 데이터 감사

모델링 전에 다음을 보고서로 남깁니다.

- 파일별 행·열 수와 키 후보
- Target 비율과 결측 여부
- 자료형, 결측률, 유일값 수, 상수 컬럼
- 투구의 시간·경기 내 순서를 재구성할 수 있는 키
- 동일 선수·경기·시즌이 train/test에 걸쳐 나타나는 방식
- Trackman 데이터의 기간, 조인 키, 중복과 커버리지
- train에만 존재하거나 test에만 존재하는 컬럼·범주
- 현재 투구가 끝난 뒤 생성되는 사후 컬럼 후보

## 2. 피처 가용성 판정

각 컬럼에는 다음 중 하나의 상태를 부여합니다.

- `AVAILABLE`: 투구 직전 확정된 원시 정보
- `HISTORY_ONLY`: 현재 행을 제외한 과거 집계로만 사용 가능
- `LEAKAGE`: 현재 투구 결과 또는 미래 정보
- `ID_ONLY`: 정렬·조인·그룹 분할에는 쓰지만 직접 피처 사용은 별도 검토
- `UNKNOWN`: 정의나 생성 시점 확인 전 사용 금지

판정은 [데이터 사전](04_data_dictionary.md)에 근거와 함께 기록합니다.

## 3. 누수 방지 규칙

### 시간 누수

누적 평균, 최근 N개 기록, 지수 이동 평균 등은 현재 행을 제외하고 계산합니다. 동일 시점 내 순서가 불명확하면 보수적으로 이전 시점까지만 사용합니다.

### Target 인코딩 누수

선수·타자·카운트별 성공률은 fold의 학습 부분에서만 계산합니다. validation 행 자신의 Target이나 validation 전체 평균이 인코딩에 섞이지 않게 합니다.

### 전처리 누수

결측치 대체, 스케일링, 범주 사전, 차원 축소, feature selection, calibration은 학습 fold로만 fit합니다.

### 그룹 누수

같은 경기나 매우 인접한 투구가 무작위로 train/validation에 섞이면 실전보다 낙관적인 점수가 날 수 있습니다. 무작위 행 분할은 진단용 이외에는 기본 검증으로 사용하지 않습니다.

## 4. 검증 설계

최종 split은 데이터의 시간 키를 확인한 뒤 정합니다. 우선순위는 다음과 같습니다.

1. 실제 평가 시점과 유사한 시간 순 holdout
2. 경기 또는 시리즈 단위 group split
3. 시즌·선수의 분포 이동을 점검하는 보조 split

각 split에서 Brier Score, Brier Skill Score, 성공률, 예측 평균, calibration curve 요약, 실행 시간을 함께 기록합니다. 한 split의 최고점보다 여러 split에서 방향이 일관적인 개선을 우선합니다.

## 5. 베이스라인 순서

다음 단계는 가설이며 데이터 감사 후 조정합니다.

1. 학습 구간 성공률을 출력하는 상수 확률 모델
2. 투수·타자·카운트 등 사전 범주 정보를 사용한 정규화된 확률 모델
3. 누수 없는 과거 이력 피처를 포함한 CPU 친화적 트리 모델
4. 서로 다른 split·seed·모델의 확률 앙상블
5. 필요할 때만 out-of-fold 예측 기반 확률 보정

GPU 모델은 실제 BSS 개선이 로딩 시간, 파일 크기, 설치 안정성 비용을 상쇄할 때만 채택합니다.

## 6. Trackman 보조 데이터

2019~2024년 데이터는 다음 순서로 검토합니다.

- 평가 대상 투구보다 과거인 레코드만 남길 수 있는가?
- 선수 ID와 구종 등 조인 키가 안정적인가?
- 한 선수에 여러 행이 매칭될 때 집계 기준이 명확한가?
- 선수별 표본 수가 적을 때 수축(shrinkage) 또는 전체 평균 대체가 필요한가?
- 매칭 실패 자체가 특정 시즌·선수군을 드러내는 편향 신호인가?

원본 Trackman 행을 무조건 조인하지 않고, cutoff 이전의 집계 피처와 표본 수를 함께 사용합니다.

## 7. 실험 채택 기준

새 아이디어는 다음을 만족할 때 채택 후보가 됩니다.

- 동일 split에서 기준 대비 BSS가 개선된다.
- 시간 또는 그룹을 바꾼 보조 split에서도 심각하게 악화되지 않는다.
- 누수 가능성을 설명하고 검사할 수 있다.
- 전체 추론 예산 안에 들어갈 것으로 측정된다.
- 오프라인 환경에서 직렬화·로드·예측이 재현된다.

실험 기록은 [템플릿](templates/experiment.md)을 복사해 작성합니다.
